# Stateless Server

![Stateless_servers_1](/home/cma/Desktop/MyLearningNotes/System-Design/Imgs/Stateless_servers_1.png)

- **Problem**: User sessions tied to specific server memory lead to "random logouts". 
  - In the 1st Image above, Bob is trying to login, the load balancer happens to send that request to server 1, so server 1 makes the note, Bob is logged in in one server's memory.
  - However, a moment later, Bob clicks on something that's a new request, the load balancer sends this one to server 2 and server 2 has never heard of Bob because the note is on server 1.
  - So server 2 looks in its own memory, finds nothing and does the only thing it can. It asks Bob to log in again.
  - That is the **Random Logout**. Bob is not being kicked out, but rather he's being sent out to a different server that doesn't have his note.
  - And with 3 servers, roughly two out of every three clicks, will land on a server that doesn't know you.
  - The servers are not allowed to remember anything about you between requests. No server keeps a note in its own memory. 
  - Instead, the note goes somewhere all of them can reach. A separate place off to the side that every server can read from and write to.
  - Now it doesn't matter which server you land on.
  - You logged in, the note gets written to that shared place, and then on the next click, whatever the load balancer picks, that server reads the same shared place, finds your note and knows you.
  - **Stateless:** A server that keeps nothing about you in its own memory is called *stateless*. Every server is now interchangeable, exactly like the load balancer needed.
    - Any server can handle any request because none of them are keeping secrets the others cannot see.
    - That shared place is very often something called Redis, an in-memory storage that is extremely fast to read from,  which matters because we're hitting it on every request.

![Stateless_servers_3](/home/cma/Desktop/MyLearningNotes/System-Design/Imgs/Stateless_servers_3.png)

- **Solution**: Externalize session state to a shared storage (e.g., Redis).
- **Key Takeaway**: Servers must be stateless and interchangeable to work with load balancers.
