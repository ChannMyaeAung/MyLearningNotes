# Problems I encountered during learning and configuring the AWS services for my HomeScout Application

1. Ran into this problem while I am trying to install node in EC2 Connect.

   ```bash
   [root@ip-172-31-34-157 ~]# nvm install node
   Downloading and installing node v26.8.1...
   Downloading https://nodejs.org/dist/v26.8.1/node-v26.8.1-linux-x64.tar.xz...
   ################################################################################################################################# 100.0%
   Computing checksum with sha256sum
   Checksums matched!
   Now using node v26.8.1
   Creating default alias: default -> node (-> v26.8.1)
   ```

   ```bash
   [root@ip-172-31-34-157 ~]# node -v
   node: error while loading shared libraries: libatomic.so.1: cannot open shared object file: No such file or directory
   [root@ip-172-31-34-157 ~]# node -v
   node: error while loading shared libraries: libatomic.so.1: cannot open shared object file: No such file or directory
   [root@ip-172-31-34-157 ~]# npm install -g pnpm
   node: error while loading shared libraries: libatomic.so.1: cannot open shared object file: No such file or directory
   ```

   How I solved it?:

   ```bash
   [root@ip-172-31-34-157 ~]# sudo dnf install -y libatomic
   Amazon Linux 2023 Kernel Livepatch repository                                                           567 kB/s |  69 kB     00:00    
   Dependencies resolved.
   ```

**Why this happens:** Starting with Node.js v25+, the Node binary dynamically links against `libatomic.so.1` for its internal operations. Amazon Linux 2023 does not ship `libatomic` by default — it must be installed separately via `dnf`. This is not a Node.js installation bug; it is a missing system dependency on the minimal Amazon Linux 2023 image.
