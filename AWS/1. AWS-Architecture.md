# AWS Architecture Steps I learnt from building a HomeScout Application

## Part 1: Backend Infrastructure (VPC + EC2 + RDS)

1. Create a VPC.
2. Attach the internet gateways to the VPC.
3. Create route tables. Edit routes for each route table.
4. Create subnets (public for EC2, private for RDS) and associate them with the appropriate route tables.
5. Create a Security Group for the EC2 instance (allow SSH/HTTP inbound).
6. Create an instance in EC2.
7. Use Connect inside the EC2 instance to do the configuration and installations there.

> For detailed instructions on each step, see the individual service notes: [VPC Architecture](vpc-architecture.md), [EC2 Setup](ec2.md), [RDS Setup](aws-rds.md).

## Part 2: Frontend Hosting with AWS Amplify

After the backend was running on EC2, the frontend (React/Next.js) was deployed using **AWS Amplify**. Amplify handles the full CI/CD pipeline every push to the GitHub `main` branch triggers an automatic build and deployment.

### Steps

1. From the AWS Console, search for **Amplify** and click **Get Started** under " Amplify Hosting".
2. Connect your GitHub repository. Amplify will ask for permission to access your repos.
3. Select the repository and branch (e.g., `main`) to deploy from.
4. Amplify detects the framework (React, Next.js, etc.) and pre-fills the build settings. Verify:
   - **Build command:** `pnpm build` (or `npm run build`)
   - **Output directory:** `.next` (for Next.js) or `build` (for CRA)
5. Click **Save and deploy**. Amplify provisions a CDN-backed hosting environment and gives you a live URL (e.g., `https://main.d1234abcdxyz.amplifyapp.com`).
6. After deployment, go to **Environment variables** in the Amplify console and add frontend env vars (e.g., `NEXT_PUBLIC_API_BASE_URL`) pointing to your API Gateway invoke URL.

### Why Amplify for Frontend Hosting?

- **Automatic CI/CD:** Every git push redeploys the frontend automatically.
- **Global CDN:** Amplify serves static assets through CloudFront edge locations, so users worldwide get fast load times.
- **Preview Deployments:** Pull requests get their own unique preview URLs, useful for testing before merging.

## Part 3: Image Storage with AWS S3

User-uploaded images (e.g., property listing photos) are stored in an **S3 bucket** instead of on the EC2 instance. This keeps the backend stateless and allows the frontend to reference images directly via S3 URLs or through the backend API.

### Steps

1. Create an S3 bucket from the AWS Console (e.g., `re-s3-images`).
2. Configure the bucket policy for public read access (`s3:GetObject`) if images are served directly to users.
3. Enable **CORS** on the bucket so the frontend can upload or fetch images cross-origin.
4. Upload objects via the console or just drag all the files to it, or programmatically from the backend using the AWS SDK (`@aws-sdk/client-s3`).

> For detailed S3 setup including versioning, encryption, and presigned URLs, see [AWS S3](aws-s3.md).

## Part 4: API Gateway as a Reverse Proxy

**AWS API Gateway** sits in front of the EC2 backend as a managed reverse proxy. All frontend API requests go through API Gateway first, which then forwards them to the EC2 instance. This adds a layer of abstraction — the frontend never talks to the EC2 IP directly.

### Why Use API Gateway in Front of EC2?

- **Single entry point:** The frontend only needs to know the API Gateway invoke URL, not the EC2 IP.
- **Cognito integration:** API Gateway natively supports Cognito authorizers, so unauthenticated requests are rejected before they ever reach your backend.
- **Stable URL:** Even if the EC2 IP changes (without an Elastic IP), you only update the API Gateway integration endpoint — the frontend URL stays the same.
- **Rate limiting & throttling:** API Gateway can throttle abusive clients before they hit your EC2 instance.

### Steps

1. Create a REST API in API Gateway with a `{proxy+}` resource for catch-all routing.
2. Set the integration type to **HTTP Proxy** and point it to the EC2 public IP on port 80 (e.g., `http://<EC2-IP>/{proxy}`).
3. Create a **Cognito Authorizer** and attach it to the `ANY` method for protected routes.
4. Deploy the API to a `prod` stage.
5. Copy the **Invoke URL** and set it as `NEXT_PUBLIC_API_BASE_URL` in your Amplify environment variables.

> For detailed API Gateway setup, see [AWS API Gateway](aws-api-gateway.md).
